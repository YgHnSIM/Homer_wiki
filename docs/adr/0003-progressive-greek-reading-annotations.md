# 점진적 그리스어 읽기 주석

## 맥락

호메로스 위키의 독자는 한국어명, 관용 라틴명, 그리스어 원형, 로마자 표기를 한 문서 안에서 함께 만난다. 이 표기층들은 서로 다른 목적을 가지지만, 기존에는 역할과 노출 위치가 일관되지 않았다. 그 결과 그리스 문자를 읽지 못하는 독자는 문장의 흐름을 잃기 쉽고, 같은 낱말이 `Aidôs`, `Aidōs`, `Aidos` 또는 `Mênis`, `Menis`처럼 서로 다른 로마자 표기로 나타나기도 한다.

반대로 모든 그리스어 출현마다 한글 읽기, 로마자, IPA를 반복하면 본문보다 주석이 앞서게 된다. 호메로스어는 이오니아어를 중심으로 아이올리스어와 고형이 섞인 전통적 시어이므로, 단일 시대 또는 단일 지역의 발음을 확정해 재현한다고 주장할 수도 없다.

## 결정

독서의 기본층은 한국어 표제어로 둔다. 그리스어 원형과 버전이 명시된 학술 전사는 다음의 제한된 위치에서만 함께 제공한다.

- 개념·엔티티·단어의 정식 표제 페이지에서는 H1 바로 아래의 읽는 법 행
- 분석·소스 문서에서는 한 개념의 첫 의미 있는 언급
- 그리스어 철자, 형태, 방언 또는 운율이 논증 대상인 구간
- 짧은 실제형의 인라인 제시 및 긴 원문의 번역·원문·실제형 전사 묶음
- 형태론·정형구 표의 분리된 전사 열

정식 표제 페이지의 프론트매터는 한국어명, 관용 라틴명, 그리스어 원형, 학술 전사 및 규약 버전의 단일 원천이다. 관용 라틴명은 제목·검색·식별을 위한 이름이고, 학술 전사는 그리스 문자를 문자 대응 중심으로 옮긴 표기이다. 두 값을 같은 필드나 같은 라벨로 취급하지 않는다.

화면에 보이는 학술 전사는 `homeric-oriented-v1`을 따른다. 이 규약은 발음기호나 음성 재현이 아니라, 한국어 독자가 원문과 편집 정보를 대조하도록 돕는 호메로스어 지향 학술 전사다. 실제 인용형은 표제형으로 대체하지 않으며, 실제 그리스어형에 대응하는 실제형 전사를 사용한다.

불확실한 장단, 디감마, 축약, 방언형, 운율적 현상, 판본 차이는 자동으로 확정하지 않는다. 근거와 검토 상태를 예외 원장에 남기고, `approved` 상태의 항목만 확정 전사로 공개한다. `review` 상태는 공개 확정값이나 검증 우회의 근거가 될 수 없다.

마이그레이션은 기존 공개 코퍼스를 명시적 레거시 허용 목록으로만 일시 유예하면서 단계적으로 진행한다. 새 페이지와 이행을 끝낸 페이지에는 즉시 새 계약을 적용한다.

## 고려한 대안

### 모든 그리스어마다 한글 읽기·전사·IPA를 붙이는 방식

활용형, 기능어, 장문 인용까지 같은 밀도로 주석을 붙이면 일반 산문이 읽기 어려워진다. 각 형태의 문헌학적 판단을 같은 품질로 보장하기도 어렵다. IPA는 비전공 독자에게 추가 학습 장벽을 만들며, 호메로스어의 역사적 발음을 확정한 것처럼 보이게 할 위험이 있다.

### 전역 HTML ruby 또는 새 Quartz 구성 요소

이 방식은 브라우저에서는 풍부할 수 있으나 Obsidian Source mode의 HTML 노이즈, Live Preview 차이, 위키링크 결합, 대량 유지보수 비용을 키운다. 첫 구현은 순수 Markdown과 프론트매터, 기존 Quartz와 Obsidian 기능만 사용한다.

### 호버·툴팁·CSS 생성 콘텐츠에 의존하는 방식

터치, 키보드, 인쇄, 복사, 검색, CSS 미적용 환경에서는 핵심 정보가 사라지거나 접근하기 어려워진다. 읽는 법 행과 첫 언급 표기는 Markdown 본문에 실제 텍스트로 남겨야 한다. popover와 Page Preview는 보조 기능일 뿐이다.

### 현대 그리스어·고전 아티카·에라스무스식 중 하나를 호메로스 발음으로 표기하는 방식

이 선택은 호메로스 시어의 혼합성과 시대 차이를 가린다. 본 결정은 발음 재현을 채택하지 않으며, 학술 전사를 음성 재생의 약속으로 표현하지 않는다.

## 결과

- 비전공 독자는 제목과 일반 산문을 한국어 중심으로 계속 읽을 수 있다.
- 독자는 첫 공개 지점과 원전 분석 지점에서 한국어명·그리스어·학술 전사의 관계를 확인할 수 있다.
- 긴 인용은 번역, 실제 그리스어형, 실제형 전사의 순서로 대조할 수 있고, 표는 그리스어와 전사를 다른 열에 둔다.
- 관용명과 전사의 혼동, ASCII와 장음 표기의 무질서한 혼용, 표제형으로 실제형을 덮는 오류를 구조적으로 줄인다.
- 자동화는 정규화와 형식 검증에 한정된다. 문헌학적 정확성은 근거를 갖춘 사람의 검토와 예외 원장에 남는 과업이다.
- 모바일에서는 표 자체만 가로로 이동해야 하며, 본문 전체의 가로 넘침이나 전사 열 숨김으로 문제를 해결하지 않는다.

## 이행과 접근성

읽는 법 행은 제목보다 낮고 본문보다 약간 약한 메타데이터로 표시한다. 배경 상자, 카드, 그림자, 배지, 아이콘, 콜아웃으로 과도하게 강조하지 않는다. CSS가 꺼져도 라벨, 순서, 값은 Markdown에서 읽혀야 한다.

기존 공개 문서 전체를 한 번에 엄격 검증하면 아직 이행하지 않은 문서 때문에 작업이 멈춘다. 따라서 기준선 인벤토리에서 확인된 기존 페이지만 레거시 목록에 일시 등록하고, 배치마다 목록에서 제거한다. 레거시 목록은 문헌학 오류를 허용하지 않으며, 새 문서를 등록하거나 더 이상 해당 조건이 없는 경로를 남기는 것은 오류로 처리한다.

## 되돌리기와 규약 변경

표시층은 순수 Markdown이므로 스타일 조정이나 읽는 법 행의 표시 방식은 데이터 손실 없이 되돌릴 수 있다. 그러나 `homeric-oriented-v1`의 전사 규칙을 바꾸는 일은 표제 페이지, 인용, 표, aliases, 예외 원장 및 검증기를 함께 검토해야 하는 호환성 변경이다.

규칙의 의미가 바뀌면 기존 버전을 조용히 덮어쓰지 않고 새 버전 식별자를 만든다. 이미 공개된 표기와 검색 별칭의 호환성, 예외 원장의 적용 규약, 마이그레이션 범위를 기록한다. IPA 또는 음성은 핵심 마이그레이션의 안정화, 확인된 독자 수요, 권위 있는 근거, 사람의 문헌학·음성학 검수, 제한된 별도 파일럿이 모두 갖추어진 뒤에만 새 ADR로 검토한다.
