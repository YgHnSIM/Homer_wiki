# 그리스어 읽기 UX 구현 계획

이 문서는 호메로스 위키의 그리스어 읽기 UX를 다른 세션에서도 같은 결정과 같은 품질 기준으로 구현하기 위한 실행 명세다. 설계 질의 25개에 대한 사용자 선택 `1-A`부터 `25-A`까지를 고정하고, 당시의 저장소 조사 결과, 채택·기각한 접근법, 데이터 계약, 파일별 변경 순서, 마이그레이션 전략, 검증 게이트를 한곳에 보존한다.

이 문서를 작성하는 작업과 실제 기능 구현은 분리한다. 이 문서가 생성된 시점에는 위키 본문, 템플릿, 검증기, Quartz 스타일, Obsidian 스타일을 그리스어 읽기 정책에 맞게 변경하지 않았다.

## 0. 새 세션의 실행 계약

사용자가 `다음 '구현 계획'에 따라 구현을 시작해`라고 지시하면 다음 절차로 작업을 시작한다.

1. 이 문서를 처음부터 끝까지 읽는다.
2. 저장소 루트의 `AGENTS.md`, `DESIGN.md`, `CONTEXT.md`를 읽는다.
3. `git status --short`와 `git diff --stat`, 관련 파일의 실제 diff를 확인한다.
4. `npm run check`로 구현 직전 기준선을 다시 측정한다.
5. 이 문서의 고정 결정을 다시 질문하지 않고 `8. 구현 단계` 순서대로 진행한다.
6. 저장소 현실이 이 문서의 스냅숏과 달라졌다면 현재 파일을 우선 보존하고, 고정된 사용자 의도를 만족하는 최소 조정만 한다.
7. 사용자 권한이 새로 필요하거나 현재 변경과 직접 충돌하여 안전한 병합이 불가능할 때만 사용자에게 묻는다.

적용 우선순위는 다음과 같다.

1. 현재 세션의 시스템·개발자 지침과 저장소의 최신 `AGENTS.md`
2. 이 문서의 `고정 결정`과 `수용 기준`
3. 이 문서의 데이터·표시 계약
4. 이 문서에 기록된 2026-08-26 저장소 스냅숏
5. 예시 문자열

예시는 구조를 설명하기 위한 것이며, 개별 그리스어 전사의 문헌학적 정확성을 대신하지 않는다. 예시와 승인된 전사 규약이 충돌하면 전사 규약과 근거 원장을 따른다.

### 0.1 반드시 지킬 작업 원칙

- `raw/` 아래 원본은 읽기만 하고 수정하지 않는다.
- 기존의 수정·추적되지 않은 파일은 사용자 소유로 취급한다. 스태시, 리셋, 체크아웃 복원, 광범위 포맷팅으로 덮어쓰지 않는다.
- 사용자가 별도로 요청하지 않은 커밋·푸시·배포는 하지 않는다.
- 실제 구현에서는 로컬 파일 편집에 `apply_patch`를 사용한다.
- UI/CSS를 변경할 때는 `frontend` 지침을 적용하고, 변경 후 `visual-qa`로 Obsidian과 Quartz를 검수한다.
- 구현 과정에서 결정되지 않은 발음을 임의로 생성하지 않는다. 확실하지 않은 형태는 검토 상태로 남긴다.
- `wiki/log.md`를 매 구현 배치마다 갱신하고, 공개 문서가 추가되거나 제목이 바뀌면 관련 색인도 같은 배치에서 갱신한다.
- 대량 치환 전에 기준선·규약·검증기를 먼저 만든다.

### 0.2 구현 전 확인할 현재 작업 트리

계획 작성 당시 다음 경로에는 사용자 소유 변경이 있었다. 새 세션에서는 이 목록이 아니라 실제 `git status`를 다시 확인하되, 여전히 존재하면 보존한다.

- 수정됨: `wiki/analyses/analysis-concept-source-matrix.md`
- 수정됨: `wiki/index.md`
- 수정됨: `wiki/log.md`
- 추적되지 않음: `.codex-remote-attachments/`
- 추적되지 않음: `raw/오뒷세이아 폴리트로포스 의미 분석.md`
- 추적되지 않음: `wiki/analyses/analysis-polytropos.md`
- 추적되지 않음: `wiki/sources/raw-2026-polytropos-notes.md`

이 계획을 구현할 때 `wiki/index.md`와 `wiki/log.md`에 기존 변경이 남아 있으면 파일 전체를 재작성하지 말고 관련 위치에 최소 패치로 병합한다.

## 1. 문제 정의와 목표

현재 위키는 한국어 독자에게 주요 이름과 개념을 한국어·라틴 문자·그리스 문자로 함께 보여 주지만, 세 표기의 역할이 일관되게 구분되지 않는다. 그리스 문자를 읽지 못하는 독자는 본문에서 자주 멈추고, 같은 문서 안에서도 `Aidôs`·`Aidōs`·`Aidos` 또는 `Mênis`·`Menis`처럼 서로 다른 로마자 표기를 만난다. 반대로 모든 그리스어 표면형 뒤에 한글 독음·로마자·IPA를 반복하면 본문보다 주석이 더 두드러져 가독성과 유지보수성이 모두 악화된다.

구현 목표는 “그리스어를 제거하는 것”도 “고대 발음을 완전히 복원하는 것”도 아니다. 목표는 그리스 문자를 읽지 못하는 한국어 일반 독자가 문장의 흐름을 잃지 않으면서도, 필요한 곳에서는 원형과 학술 전사에 접근할 수 있게 하는 것이다.

핵심 전략은 다음 한 문장으로 요약한다.

`한국어 표제어를 독서의 기본층으로 두고, 페이지별 첫 완전 공개와 원전 분석 구간에서만 그리스어 원형과 버전이 명시된 학술 전사를 제공한다.`

### 1.1 성공 상태

구현이 끝나면 다음 경험이 성립해야 한다.

- 비전공 독자는 제목과 일반 산문을 한국어 중심으로 연속해서 읽을 수 있다.
- 첫 언급이나 페이지 상단만 보면 한국어 명칭, 원어, 학술 전사의 관계를 이해할 수 있다.
- 긴 원문은 번역, 실제 그리스어형, 그 실제형의 학술 전사를 행 단위로 대조할 수 있다.
- 형태론 표에서는 그리스어와 전사가 서로 다른 열에 있어 빠르게 대응시킬 수 있다.
- 관용 영어명과 학술 전사가 서로 다른 정보라는 점이 드러난다.
- Source mode, Live Preview, Obsidian Reading view, 공개 Quartz, 모바일에서 핵심 정보가 사라지지 않는다.
- 검색, 복사, 링크, 인쇄 또는 CSS 미적용 상태에서도 핵심 읽기 정보가 일반 텍스트로 남는다.
- 전사 규약의 버전과 예외 근거가 추적 가능하다.
- 미확정 형태가 확정값처럼 노출되지 않는다.

### 1.2 명시적 비목표

첫 구현에서는 다음을 하지 않는다.

- 모든 그리스어 출현부에 한글 읽기·로마자·IPA를 반복 부착
- “정확한 호메로스 발음” 또는 “원어민 발음”을 제공한다고 주장
- IPA 일괄 생성
- 자동 TTS 또는 음성 파일 생성
- 전역 HTML `ruby` 적용
- `title` 속성이나 호버만으로 핵심 정보를 숨김
- CSS `content`만으로 읽기 정보를 생성
- 모든 굴절형·기능어에 대응하는 빈 문서 생성
- 형태론적 판단이 필요한 전사를 무검수 자동 확정
- `raw/` 원문 정리 또는 수정
- 그리스어 읽기 UX와 무관한 대규모 템플릿 재설계

## 2. 용어 계약

구현 문서와 UI에서 다음 용어를 일관되게 사용한다.

| 용어 | 의미 | 예시 | 사용 규칙 |
|:---|:---|:---|:---|
| 한국어 표제어 | 한국어 독자가 본문에서 기본적으로 읽는 관용 명칭 또는 번역어 | 아킬레우스, 메니스, 오뒷세이아 | 기본 독서층이다. 역사적 발음의 정확한 복원이라고 부르지 않는다. |
| 관용 라틴명 | 영어·국제 학술 관행에서 굳어진 이름 | Achilles, Odyssey, Menis | 제목·검색·식별에 사용한다. 학술 전사와 동일시하지 않는다. |
| 그리스어 원형 | 사전 표제형 또는 작품·인명의 대표 원어형 | Ἀχιλλεύς, μῆνις, Ὀδύσσεια | 문헌 확인층이다. |
| 학술 전사 | 그리스 문자를 버전이 고정된 로마자 규약으로 옮긴 표기 | Akhilleús 등 | “발음기호”라고 부르지 않는다. |
| 실제 인용형 | 원전의 해당 위치에 실제로 나타나는 굴절·활용형 | μῆνιν, ὀδυσσάμενος | 인용에서는 표제형으로 대체하지 않는다. |
| 실제형 전사 | 실제 인용형에 대응하는 학술 전사 | 해당 실제형의 전사 | 원문 행과 일대일로 대응시킨다. |
| 한글 읽기 | 한국어 화자가 이름을 식별하고 소리 내어 읽기 위한 관용·근사 표기 | 메니스 | “정확한 재구 발음”이라는 표현을 쓰지 않는다. |
| 읽는 법 행 | 표제 페이지의 H1 바로 아래에 놓는 고정 메타데이터 한 줄 | 한국어명 · 원어 · 학술 전사 | 첫 완전 공개로 계산한다. |
| 전사 예외 | 기본 규칙만으로 확정할 수 없거나 승인된 관용 처리가 필요한 형태 | 문헌 근거가 필요한 개별 형태 | 예외 원장에서 상태와 근거를 관리한다. |

UI와 편집 지침에서 피할 표현은 다음과 같다.

- 발음기호
- 정확한 호메로스 발음
- 당시 실제 발음
- 고대 그리스 원어민 발음

대신 다음 표현을 사용한다.

- 학술 전사
- 한글 읽기 또는 한글 근사음
- 호메로스어 지향 전사
- 호메로스기 지향 읽기 관행

## 3. 고정 결정 등록부

다음 25개 항목은 사용자 승인 사항이다. 구현 중 취향에 따라 바꾸거나 다시 질문하지 않는다.

| 번호 | 고정 결정 | 구현상 의미 |
|:---:|:---|:---|
| 1-A | 1차 목표는 비전공 한국어 독자의 연속 독서와 개념 인식이다. | 역사음 재현보다 읽기 흐름을 우선한다. |
| 2-A | 필수 UX는 Obsidian Source/Live Preview와 공개 Quartz에서 모두 작동해야 한다. | 렌더러 전용 기능에 핵심 정보를 맡기지 않는다. |
| 3-A | 그리스어는 첫 언급과 문헌학·인용 구간에 유지하고, 일반 산문의 반복 언급에서는 생략한다. | 전면 삭제와 매번 반복을 모두 피한다. |
| 4-A | 기본 첫 공개 순서는 `한국어 표제어(그리스어 원형, 학술 전사)`이며, 표제 페이지에는 상단 읽는 법 행을 둔다. | 관용 라틴명은 제목·별칭에서 분리 관리한다. |
| 5-A | 확립된 한국어 관용 표기는 유지하되 정확한 재구 발음이라고 주장하지 않는다. | 기존 독자의 친숙성과 학술적 정직성을 함께 지킨다. |
| 6-A | 전사는 Bozzone의 원칙을 참고한 `homeric-oriented-v1`로 버전 관리한다. | 악센트·모음 길이를 가능한 범위에서 보존하고, χ는 `kh`, 호메로스기 υ는 `u`를 기본으로 한다. 관용명은 별도 필드다. |
| 7-A | 첫 범위에서 IPA와 음성을 제외한다. | 빈 IPA 필드를 대량 추가하지 않고 후속 결정으로 분리한다. |
| 8-A | 페이지 제목·사이드바·색인은 한국어와 관용 라틴명을 쓴다. 단어 사전은 영단어 우선 예외를 허용한다. | 제목에서 그리스어와 학술 전사를 제거하고 읽는 법 행으로 이동한다. |
| 9-A | 긴 인용은 `한국어 번역 → 그리스어 원문 → 실제형 학술 전사` 순서다. | 독자가 의미를 먼저 잡고 원문을 대조한다. |
| 10-A | 그리스어 1–3어는 인라인, 4어 이상 또는 완전한 절·시행은 3행 형식이다. | 긴 괄호 사슬과 단어별 ruby를 금지한다. |
| 11-A | 형태론·정형구 표는 그리스어와 학술 전사를 별도 열로 둔다. | 한 셀의 혼합 표기를 분리하고 한국어 풀이 열을 유지한다. |
| 12-A | 색인과 Mermaid는 한국어·관용 라틴명으로 간결하게 유지한다. 그리스어 자체가 분석 대상일 때만 원어를 포함한다. | 탐색 UI에 삼중 표기를 반복하지 않는다. |
| 13-A | 개념·엔티티·단어의 정식 페이지 프론트매터가 단일 원천이며, 읽는 법 행은 이를 검증 가능한 방식으로 반영한다. | 본문과 메타데이터가 어긋나면 검증 실패다. |
| 14-A | 첫 구현은 순수 Markdown·프론트매터와 기존 Quartz/Obsidian만 사용한다. | 새 Quartz 컴포넌트와 전역 ruby를 만들지 않는다. |
| 15-A | 정형적 서식·정규화는 자동 검증하고, 문헌학적 판단은 근거가 있는 수동 검토와 예외 원장으로 관리한다. | 자동 전사기를 진실의 원천으로 만들지 않는다. |
| 16-A | 공개 그리스어 포함 문서 전체를 단계적으로 마이그레이션한다. | 파일 전부를 한 번에 바꾸지 않고 배치별 게이트를 둔다. |
| 17-A | 대표 문서 4개로 먼저 시험한다. | 개념·엔티티·단어·소스 유형을 각각 하나씩 검증한다. |
| 18-A | 화면에 보이는 학술 전사는 새 규약으로 통일하고, 기존·ASCII 표기는 aliases 또는 매핑에 보존한다. | 검색 호환성을 잃지 않되 본문 표기를 혼용하지 않는다. |
| 19-A | 상세 편집·전사 규약과 짧은 공개 읽기 안내를 별도 문서로 제공한다. | 편집자용 근거와 독자용 설명의 밀도를 분리한다. |
| 20-A | 읽는 법 행은 작고 차분한 메타데이터로 보이게 한다. | 카드, 콜아웃, 배경 상자, 그림자, 과한 강조를 쓰지 않는다. |
| 21-A | 모바일 형태론 표는 표 컨테이너 안에서 가로 스크롤한다. | 본문 전체의 가로 넘침이나 글자 축소로 해결하지 않는다. |
| 22-A | 독립 표제 페이지가 없는 그리스어형은 현장에서 전사한다. 반복적으로 중요한 용어만 페이지 후보가 된다. | 모든 형태에 빨간 링크·빈 문서를 만들지 않는다. |
| 23-A | 불확실한 형태는 review로 남기고, 형태·제안·이유·출처·상태를 예외 원장에 적는다. 승인된 예외만 엄격 검증을 통과한다. | 미확정 제안은 사실처럼 공개하지 않는다. |
| 24-A | 자동·문헌학·Obsidian·Quartz 반응형 검수가 모두 통과해야 파일럿을 확장한다. | 한 환경의 성공으로 전체 배포를 승인하지 않는다. |
| 25-A | IPA·음성은 핵심 마이그레이션 안정화, 사용자 수요, 권위 있는 근거, 인간 검수가 모두 있을 때 별도 파일럿으로 검토한다. | 현재 구현 범위에 슬쩍 포함하지 않는다. |

## 4. 표시 UX 계약

### 4.1 정식 개념·엔티티 페이지

프론트매터 `title`과 문서 H1은 다음 형식을 사용한다.

~~~text
한국어 표제어 (관용 라틴명)
~~~

예:

~~~markdown
title: 아킬레우스 (Achilles)

# 아킬레우스 (Achilles)
~~~

그리스어와 학술 전사를 제목에 넣지 않는다. H1 바로 아래, 첫 일반 본문보다 앞에 다음 순서의 읽는 법 행을 둔다.

~~~markdown
**[[greek-reading-guide|읽는 법]]**: 아킬레우스 · **원어**: Ἀχιλλεύς · **학술 전사**: *Akhilleús*
~~~

이 행은 해당 페이지의 첫 완전 공개로 계산한다. 따라서 이어지는 일반 산문의 첫 문장은 `아킬레우스`만 써도 된다. 문헌학 섹션에서는 원형·굴절형을 다시 제시할 수 있다.

### 4.2 단어 사전 페이지

`words/word-*.md`는 현대 영어 표제어를 탐색 기준으로 삼으므로 다음 제목 예외를 사용한다.

~~~text
English headword (한국어 표제어)
~~~

예:

~~~markdown
title: Odyssey (오뒷세이아)

# Odyssey (오뒷세이아)
~~~

H1 아래 읽는 법 행은 동일한 순서를 사용한다.

~~~markdown
**[[greek-reading-guide|읽는 법]]**: 오뒷세이아 · **원어**: Ὀδύσσεια · **학술 전사**: *Odússeia*
~~~

여기서 `Odyssey`는 현대 영어 표제어·관용명이고 `Odússeia`는 그리스어 학술 전사다. 둘을 한 필드나 한 라벨로 합치지 않는다. 예시의 실제 전사값은 `homeric-oriented-v1` 규약과 문헌학 검수를 거쳐 확정한다.

### 4.3 분석·소스·일반 산문의 첫 언급

별도의 읽는 법 행이 없는 문서에서는 한 개념의 첫 의미 있는 언급만 다음 순서를 사용한다.

~~~markdown
[[concept-aidos|아이도스]](αἰδώς, *승인된 학술 전사*)
~~~

이후 같은 의미의 반복 언급은 `아이도스`만 사용한다. 다음 경우에는 다시 그리스어를 표시할 수 있다.

- 다른 굴절형이 분석 대상인 경우
- 철자·방언·형태론 차이가 논증의 일부인 경우
- 직접 원문 인용인 경우
- 서로 비슷한 두 그리스어형을 대조하는 경우

첫 언급 판정은 문서 전체를 기준으로 하되, 초록·요약에서 완전 공개한 뒤 본문이 지나치게 멀리 떨어져 있으면 핵심 섹션 첫머리에 짧게 재안내할 수 있다. 이 예외는 자동화하지 않고 편집 판단으로 둔다.

### 4.4 짧은 그리스어

그리스어 어휘가 1–3개이고 완전한 절·시행이 아닐 때는 인라인으로 둔다.

~~~markdown
메니스(μῆνις, *승인된 실제 전사*)는 ...
~~~

표제형과 실제형을 구분한다. 원전에 `μῆνιν`이 있으면 `μῆνις`의 전사를 붙여 덮지 않고 `μῆνιν` 자체의 전사를 붙인다.

### 4.5 긴 원문·절·시행

그리스어가 4어 이상이거나 문법적으로 완결된 절·시행이면 목록 세 줄을 사용한다. 순서는 고정이다.

~~~markdown
- **번역**: 한국어 번역문
- **원문**: *그리스어 실제 인용문*
- **학술 전사**: *위 원문과 행 단위로 대응하는 실제형 전사*
~~~

추가 주석이 필요하면 같은 목록의 하위 항목으로 둔다.

~~~markdown
  - **주석**: 판본 차이, 형태론, 운율 또는 번역상의 유의점
~~~

직접 인용에는 블록인용 `>`를 쓰지 않는 저장소 규칙을 그대로 지킨다. 번역이 여러 개면 번역 항목을 분리하되 원문과 전사의 대응 관계를 흐리지 않는다. 여러 시행은 시행별로 같은 세 줄 묶음을 반복하거나, 원문의 행바꿈을 전사에서도 정확히 보존한다.

### 4.6 형태론·정형구 표

새 표는 최소 다음 열을 분리한다.

| 그리스어 실제형 | 학술 전사 | 표제형·형태론 | 한국어 풀이 | 근거 |
|:---|:---|:---|:---|:---|
| 실제 그리스어형 | 같은 실제형의 전사 | 표제형, 격·수·성 또는 시제·태·법 | 문맥상 뜻 | 서·행 또는 사전 |

정형구 표도 최소한 `희랍어 정형구`와 `학술 전사`를 분리한다. 기존처럼 `그리스어 (*translit*)`를 한 셀에 섞어 두지 않는다.

모바일에서는 Quartz의 기존 `.table-container` 안에서 표만 좌우로 이동해야 한다. 다음 해결책은 금지한다.

- 본문 전체에 `overflow-x`를 부여
- 표 글자를 읽기 어려울 정도로 축소
- 그리스어와 전사 열을 다시 한 셀에 합침
- 모바일에서 전사 열을 숨김

### 4.7 제목·색인·사이드바·Mermaid

- 개념·엔티티 제목: `한국어 (관용 라틴명)`
- 단어 사전 제목: `English headword (한국어)`
- `wiki/index.md`, `words/index.md`, `wiki/overview.md`의 탐색 라벨: 한국어 또는 관용 라틴명
- 일반 관계도·서사 흐름 Mermaid: 한국어·관용 라틴명만 사용
- 그리스어 철자나 형태 변화 자체가 도표의 증거일 때: 그리스어를 사용할 수 있다. 필요한 전사는 같은 노드의 짧은 둘째 줄 또는 도표 직후의 범례에서 제공한다.
- Mermaid 노드에 모든 표기층을 반복하지 않는다.
- Mermaid 노드 라벨 시작 또는 `<br/>` 직후에 `1. `, `- ` 같은 목록 문법을 쓰지 않는다.

### 4.8 시각적 계약

읽는 법 행은 정보 계층상 제목보다 낮고 일반 본문보다 약간 약한 메타데이터다.

- 본문보다 약간 작은 크기
- `--gray` 또는 그에 준하는 기존 테마 토큰 사용
- 본문과 같은 고전적 serif 계열
- 충분한 대비와 최소 1.5 수준의 행간
- 링크는 기존 내부 링크 규칙 유지
- 배경, 테두리 상자, 그림자, 배지, 아이콘, 콜아웃 사용 금지
- 줄이 길어지면 자연스럽게 줄바꿈
- 작은 화면에서 페이지 전체 가로 넘침 금지

핵심 정보는 Markdown 본문에 실제 텍스트로 존재해야 한다. CSS가 꺼져도 순서와 의미가 유지되어야 한다.

### 4.9 호버와 미리보기의 지위

현재 Obsidian Page Preview와 Quartz popover는 보조 UX로 활용할 수 있다. 그러나 모바일 Quartz에서는 popover를 사용할 수 없고 키보드·인쇄 환경에서도 일관되지 않으므로, 호버는 수용 기준이 아니다. 읽는 법 행과 첫 언급 표기만으로 핵심 과업을 완료할 수 있어야 한다.

## 5. 단일 원천과 프론트매터 계약

### 5.1 정식 표제 페이지 필드

`wiki/concepts/concept-*.md`, `wiki/entities/entity-*.md`, `words/word-*.md`의 마이그레이션된 페이지는 다음 필드를 사용한다.

~~~yaml
korean_name: 아킬레우스
conventional_latin: Achilles
greek: "Ἀχιλλεύς"
transliteration: "Akhilleús"
transliteration_system: homeric-oriented-v1
cssclasses: [greek-reading-page]
~~~

필드 의미는 다음과 같다.

| 필드 | 형식 | 규칙 |
|:---|:---|:---|
| `korean_name` | 비어 있지 않은 문자열 | 제목과 읽는 법 행의 한국어 값이다. |
| `conventional_latin` | 비어 있지 않은 문자열 | 관용 영어명·라틴 문자 표제다. 학술 전사와 같아도 역할은 별개다. |
| `greek` | NFC 정규화된 비어 있지 않은 문자열 | 대표 표제형 한 개다. |
| `transliteration` | 비어 있지 않은 문자열 | 승인된 `homeric-oriented-v1` 표기다. 미확정 제안을 넣지 않는다. |
| `transliteration_system` | 고정 문자열 | 첫 버전에서는 반드시 `homeric-oriented-v1`이다. |
| `cssclasses` | 문자열 배열 | 기존 값이 있으면 보존하고 `greek-reading-page`를 추가한다. |

단어 사전의 기존 `word` 필드는 유지한다. `greek_root`에 원형·전사·품사를 한 문자열로 섞어 둔 기존 데이터는 호환성을 고려해 단계적으로 분해한다. 마이그레이션 후 `greek`와 `transliteration`이 읽기 UI의 단일 원천이며, `greek_root`가 계속 필요하다면 어원·형태론 설명용 보조 필드로만 사용하고 동일 정보를 충돌하게 중복하지 않는다.

대표 이형이 꼭 필요한 경우에만 다음 필드를 사용한다.

~~~yaml
greek_variants:
  - "Ὀδυσεύς"
  - "Ὀδυσσεύς"
~~~

모든 격변화·활용형을 `greek_variants`에 넣지 않는다. 본문 실제형은 해당 인용이나 형태론 표에서 관리한다.

### 5.2 제목 계산 규칙

검증 가능한 제목 규칙은 다음과 같다.

- 개념·엔티티: `{korean_name} ({conventional_latin})`
- 단어: `{표시용 word} ({korean_name})`
- H1은 프론트매터 `title`과 문자 단위로 같아야 한다.
- 제목과 H1에는 `greek` 또는 `transliteration`을 덧붙이지 않는다.
- 기존 제목의 긴 설명은 H1 뒤 별도 한 문장 또는 정의 섹션으로 옮긴다.

`word`가 소문자 사전 표제형이고 제목에서 대문자 고유 제목을 써야 하는 문서는 기존 서지·영어 관행을 근거로 표시값을 유지한다. 자동으로 첫 글자를 바꾸지 않는다.

### 5.3 읽는 법 행 계산 규칙

마이그레이션된 표제 페이지에서 읽는 법 행은 H1 바로 다음의 첫 비어 있지 않은 본문 줄이어야 한다.

~~~text
**[[greek-reading-guide|읽는 법]]**: {korean_name} · **원어**: {greek} · **학술 전사**: *{transliteration}*
~~~

공백, 구분점, 라벨 순서까지 표준화한다. 수작업으로 다른 설명을 끼워 넣지 않는다. 읽는 법 행의 값은 프론트매터와 정확히 같아야 한다.

`aliases`에는 검색과 기존 링크 호환을 위해 다음을 보존할 수 있다.

- 기존 전체 제목
- 관용 라틴명
- 그리스어 원형과 중요한 이형
- 승인된 학술 전사
- 기존 장음 표기·ASCII 검색형
- 주요 한국어 별칭

별칭은 독자 표시층을 대신하지 않는다. 중복, 빈 값, 현재 제목과 불필요하게 같은 값은 정리한다.

### 5.4 불확실한 전사

불확실한 전사를 임의로 `transliteration`에 확정하지 않는다.

1. 문서의 `status`와 `status/review` 태그를 맞춘다.
2. `scripts/greek-transliteration-exceptions.json`에 검토 항목을 추가한다.
3. 제안값은 원장의 `proposal`에만 둔다.
4. 공개 본문에서 확정값처럼 기울임꼴로 표시하지 않는다.
5. `review` 상태의 예외는 엄격 검증을 면제하지 않는다.
6. 해당 페이지는 승인 또는 표준 규칙으로 해결되기 전까지 레거시 허용 목록에서 제거하지 않는다.
7. `approved` 상태가 된 예외만 읽는 법 행·인용·표의 확정 전사로 사용할 수 있다.

따라서 `review`는 “검증을 통과시키는 우회로”가 아니라 미완료 작업을 가시화하는 상태다.

## 6. 전사 규약 `homeric-oriented-v1`

### 6.1 규약의 목적

이 규약은 음성학적 녹음이 아니라 독서와 문자 대응을 돕는 학술 전사다. 호메로스어가 단일 도시·단일 시기의 자연 구어가 아니라 이오니아어 중심에 아이올리스어·고형이 섞인 전통적 시어라는 점을 공개 안내에 명시한다.

규약 문서 `docs/editorial/homeric-oriented-transliteration-v1.md`를 생성하여 다음을 한곳에서 정의한다.

- 적용 범위와 비적용 범위
- 대문자·소문자 대응
- 모음과 장모음
- 이중모음
- 거친숨·매끈숨
- 예음·억음·곡절음의 로마자 처리
- 자음, 겹자음, ζ·ξ·ψ
- χ를 `kh`로 적는 규칙
- 호메로스기 υ를 `u`로 적는 규칙
- ι 아래첨자와 분음부호
- 어두 대문자와 고유명사
- 구두점과 아포스트로피
- 단어 경계와 생략
- 실제 굴절형 전사
- 관용명과 학술 전사의 분리
- 알려진 한계와 이설
- Unicode NFC 정규화
- 예외 원장 사용법
- 버전 변경 정책

악센트와 모음 길이는 가능한 한 보존하되, 동일 기호에 두 기능을 모호하게 겹쳐 놓지 않도록 규약 표에서 예를 들어 설명한다. 기존 `Mênis`·`mēnis`·`Menis` 가운데 무엇을 화면 표준으로 삼는지는 이 규약의 표와 출처를 통해 한 번만 확정한다.

### 6.2 근거의 최소 기준

규약을 작성할 때 다음 종류의 근거를 우선한다.

- Chiara Bozzone, `Homer's Living Language`의 transliteration note
- 신뢰할 수 있는 고대 그리스어 문법·사전
- 실제 사용 판본의 원문
- 악센트·장단·방언을 다루는 학술 자료
- Unicode의 Greek 정규화 설명

개별 형태에 대해 자동 변환 결과와 판본이 다르면 판본과 문헌학 검토를 우선한다. 블로그·무출처 발음 사이트·자동 TTS를 승인 근거로 쓰지 않는다.

### 6.3 전사 예외 원장

`scripts/greek-transliteration-exceptions.json`은 다음 구조로 시작한다.

~~~json
{
  "schemaVersion": 1,
  "transliterationSystem": "homeric-oriented-v1",
  "entries": [
    {
      "greek": "NFC 그리스어형",
      "proposal": "제안 전사",
      "approvedTransliteration": null,
      "reason": "기본 규칙으로 확정할 수 없는 이유",
      "sources": ["검증 가능한 서지 또는 원전 위치"],
      "status": "review",
      "locations": ["wiki/...md:문맥 식별자"],
      "reviewedBy": null,
      "reviewedAt": null
    }
  ]
}
~~~

허용 상태는 `review`, `approved`, `rejected`다.

- `review`: 제안은 있으나 공개 확정값과 검증 예외로 사용할 수 없다.
- `approved`: `approvedTransliteration`, 근거, 검토자, 검토일이 모두 있어야 한다.
- `rejected`: 거부 이유가 있어야 하며 어떤 문서도 해당 제안을 확정값으로 사용하면 안 된다.

원장 안의 그리스어 키는 NFC로 정규화하고, 같은 `greek`·같은 규약 조합의 중복 항목을 금지한다. 더 이상 어떤 문서에서도 참조하지 않는 승인 예외는 stale 오류로 처리한다.

## 7. 검증·마이그레이션 아키텍처

### 7.1 왜 단계적 엄격화가 필요한가

계획 시점의 공개 코퍼스는 그리스어 문자열이 약 1,300회이고 서로 다른 정규화 문자열이 600개 이상이다. 새 규칙을 전역 필수로 한 번에 켜면 아직 손대지 않은 문서 때문에 모든 검증이 실패한다. 반대로 검증을 마지막에 붙이면 새 문서도 계속 구형 형식으로 늘어난다.

따라서 “새 규칙을 즉시 적용하되 기존 문서는 명시적인 임시 목록으로만 유예”하는 방식을 사용한다.

### 7.2 임시 레거시 허용 목록

`scripts/legacy-greek-reading-pages.json`을 생성한다.

~~~json
{
  "schemaVersion": 1,
  "reason": "pre-homeric-oriented-v1 migration",
  "pages": [
    "wiki/concepts/concept-aidos.md"
  ]
}
~~~

규칙은 다음과 같다.

- 기준선 인벤토리에서 기존 그리스어 포함 공개 문서만 등록한다.
- 새로 생성되는 공개 문서는 등록할 수 없다.
- 마이그레이션을 완료한 페이지는 같은 패치에서 목록에서 제거한다.
- 존재하지 않거나 그리스어가 더 이상 없는 경로가 남으면 stale 오류다.
- 중복·절대경로·`..`·`raw/`·`docs/` 경로를 금지한다.
- 최종 완료 시 `pages`는 빈 배열이어야 한다. 안정화 후 파일 자체를 제거하고 검증기를 전역 엄격 모드로 단순화할 수 있다.

레거시 목록은 문헌학 오류를 승인하지 않는다. 단지 마이그레이션되지 않은 페이지의 새 표시 계약을 일시 유예한다.

### 7.3 새 스크립트

다음 파일을 추가한다.

| 파일 | 책임 |
|:---|:---|
| `scripts/greek-reading-inventory.mjs` | 공개 Markdown의 그리스어 출현, 문서별 밀도, 제목·본문·표·코드 펜스·인용 구간을 보고하고 감사 문서를 생성한다. |
| `scripts/greek-reading-validation.mjs` | 프론트매터, 제목, 읽는 법 행, NFC, 규약 버전, 표·인용 구조, 예외·레거시 원장을 검증한다. |
| `scripts/test-greek-reading-tooling.mjs` | 정상·실패 fixture로 새 검증기의 회귀 테스트를 수행한다. |
| `scripts/legacy-greek-reading-pages.json` | 미마이그레이션 공개 페이지의 임시 유예 목록이다. |
| `scripts/greek-transliteration-exceptions.json` | 문헌학적 예외와 검토 상태의 근거 원장이다. |

기존 `scripts/wiki-document-validation.mjs`와 새 스크립트가 같은 프론트매터 파싱·코드 펜스 제외 로직을 중복하게 될 때만 `scripts/wiki-markdown-utils.mjs`를 추출한다. 추출한다면 기존 동작을 회귀 테스트로 먼저 고정하고, 관련 없는 구조 개편은 하지 않는다.

### 7.4 인벤토리 범위

기본 공개 범위는 다음이다.

- `index.md`
- `wiki/**/*.md` 중 Quartz 제외 경로가 아닌 문서
- `words/**/*.md`

다음은 구분해서 보고한다.

- `wiki/log.md`: 작업 이력으로 집계는 하되 마이그레이션 대상에서 제외
- `wiki/meta/**`: 내부 문서로 공개 마이그레이션 대상에서 제외
- `_template.md`: 템플릿 범주로 별도 집계
- YAML frontmatter
- 일반 산문
- Markdown 표
- Mermaid·코드 펜스
- 직접 인용 후보
- 링크 별칭과 제목

그리스 문자 판정은 Unicode Script/Script_Extensions와 결합부호를 고려하고, 비교 키는 NFC로 정규화한다. 단순한 `[Ͱ-Ͽ]` 범위만 사용해 Greek Extended 문자를 누락하지 않는다.

### 7.5 자동 검증 항목

엄격 검증은 최소 다음을 확인한다.

#### 정식 표제 페이지

- 필수 새 필드의 존재와 타입
- 문자열의 앞뒤 공백 없음
- `greek`과 중요한 `greek_variants`의 NFC
- `transliteration_system === "homeric-oriented-v1"`
- `cssclasses`에 `greek-reading-page` 존재
- 페이지 유형별 `title` 계산 결과 일치
- H1과 `title`의 정확한 일치
- 제목·H1에 `greek` 또는 `transliteration`이 중복되지 않음
- H1 바로 아래 읽는 법 행 존재
- 읽는 법 행의 라벨·순서·구분점 일치
- 읽는 법 행의 값이 프론트매터와 정확히 일치
- `aliases`에 필요한 기존 검색형이 보존됨

#### 산문·인용·표

- 표준 읽는 법 행을 제외한 명백한 구형 삼중 제목 패턴 보고
- 4어 이상 또는 완전 시행으로 표시된 원문 블록의 `번역 → 원문 → 학술 전사` 순서
- 세 줄 중 하나가 빠진 원문 블록 보고
- 원문과 전사 행 수 불일치 보고
- 그리스어 열이 있는 형태론·정형구 표에 별도 학술 전사 열 존재
- 한 셀의 `Greek (*translit*)` 구형 혼합 패턴 보고
- 인용에 블록인용을 사용한 경우 기존 규칙과 함께 오류
- 미승인 예외 전사가 확정값으로 사용된 경우 오류

“완전한 절인지”, “전사가 문헌학적으로 옳은지”, “첫 언급 재안내가 필요한지”는 자동 검증으로 단정하지 않는다. 스크립트는 확실한 구조 오류만 실패시키고, 애매한 후보는 보고서에 경고로 낸다.

#### 원장

- JSON 스키마와 버전
- 상대 POSIX 경로만 허용
- 중복·stale 레거시 경로
- 새 파일의 부당한 레거시 등록
- 예외 상태별 필수 필드
- NFC와 중복 키
- 미참조 승인 예외
- `review` 예외를 검증 우회로로 사용하지 않았는지

### 7.6 검사 모드

다음 명령 계약을 추가한다.

~~~json
{
  "scripts": {
    "check:greek": "node scripts/greek-reading-validation.mjs --strict && node scripts/test-greek-reading-tooling.mjs",
    "report:greek": "node scripts/greek-reading-inventory.mjs --report",
    "check": "node scripts/validate-wiki.mjs && node scripts/build-concept-source-matrix.mjs --check && node scripts/test-wiki-tooling.mjs && npm run check:greek"
  }
}
~~~

- `npm run report:greek`은 전체 현황과 유예 문서를 보여 주되 성공 종료한다. 파싱·스키마 오류는 실패한다.
- `npm run check:greek`은 마이그레이션 완료 페이지와 새 페이지에 엄격 규칙을 적용하고, 원장 무결성을 검사한다.
- `npm run check`은 기존 검사와 새 검사를 모두 수행하는 최종 로컬·CI 게이트다.

GitHub Actions는 이미 `npm run check`를 실행하므로, 워크플로 파일은 새 명령이 기존 체인에 포함되는 한 변경하지 않는다. 불필요한 새 의존성도 추가하지 않는다. 현재 `yaml` 패키지를 재사용한다.

### 단계 2. 공개 읽기 안내 생성

이 문서는 공개되어야 하므로 `wiki/meta/`에 두지 않는다. 프론트매터는 `type/meta`를 사용하고, `scripts/wiki-document-validation.mjs`의 경로별 type 판정에서 이 공개 루트 메타 페이지를 명시적으로 인정한다. `wiki/index.md`와 필요하면 루트 `index.md` 또는 `wiki/overview.md`에서 실제 작성된 페이지로 링크한다.

4. `homeric-oriented-v1`은 발음 녹음이 아니라는 한계
5. 호메로스어가 혼합된 시어라는 짧은 설명
6. IPA와 음성이 현재 없는 이유

- 제목과 H1에서 그리스어를 제거한다.
- H1 바로 아래 표준 읽는 법 행을 둔다.
- 형태론·정형구 표를 별도 전사 열 구조로 바꾼다.
- 긴 원문 예시를 번역·원문·전사 순서로 바꾼다.
- 일반 산문 반복 원칙을 템플릿 주석에 짧게 남긴다.

`wiki/concepts/_template.md`를 새로 만들 때 `scripts/wiki-document-validation.mjs`의 개념 파일명 규칙이 엔티티·단어 템플릿처럼 `_template.md`를 허용하게 수정한다.

`AGENTS.md`에는 이 문서 전체를 복제하지 말고 다음 운영 규칙만 추가한다.

- 표기 용어와 순서
- 첫 언급·반복·긴 인용·표 규칙
- 표제 페이지 필드와 규약 버전
- 공개 읽기 안내와 상세 편집 규약의 위치
- IPA·음성 비범위
- 검증 명령

`CONTEXT.md`에는 정보 구조와 문서 역할, `DESIGN.md`에는 읽는 법 행·모바일 표의 시각 계약을 기록한다.

완료 조건:

- 세 템플릿이 동일한 핵심 필드와 읽는 법 행 계약을 공유한다.
- 페이지 유형별 제목 예외가 명확하다.
- 새 페이지를 템플릿에서 만들면 레거시 목록 없이 검증을 통과한다.
- `AGENTS.md`와 상세 규약이 충돌하거나 같은 표를 중복 소유하지 않는다.
- 기존 템플릿 내용의 학술 구조가 불필요하게 삭제되지 않았다.

### 단계 4. 인벤토리·검증·테스트 도구 구현

생성·수정 파일은 `7`을 따른다. 먼저 테스트에서 실패 사례를 고정하고 검증기를 구현한다.

구현 순서:

1. Markdown·프론트매터 읽기와 NFC 도우미
2. 공개 범위 인벤토리
3. 레거시 목록 생성과 무결성 검사
4. 정식 표제 페이지 필드·제목·읽는 법 행 검사
5. 예외 원장 스키마 검사
6. 표·긴 원문의 확실한 구조 검사
7. 보고 모드와 엄격 모드
8. `package.json` 및 CI 경로 연결

완료 조건:

- 정상·실패 fixture가 모두 의도한 결과를 낸다.
- 기존 `npm run check`의 검사가 회귀하지 않는다.
- 새 페이지가 구형 형식이면 실패한다.
- 아직 마이그레이션하지 않은 기존 페이지는 레거시 목록 때문에만 통과하고 보고서에는 남는다.
- 레거시·예외 원장의 중복과 stale 항목이 실패한다.
- 검사기가 문헌학적으로 애매한 값을 독단적으로 “정답” 처리하지 않는다.
- 감사 보고서를 같은 입력에서 재생산할 수 있다.

### 단계 5. 4개 파일럿 문서 마이그레이션

파일럿은 다음 네 문서로 고정한다.

1. `wiki/concepts/concept-aidos.md`
2. `wiki/entities/entity-achilles.md`
3. `words/word-odyssey.md`

선정 이유:

- `concept-aidos.md`: 본문 삼중 표기와 용어 변형이 많은 개념 페이지
- `entity-achilles.md`: 관용 영어명과 학술 전사, 정형구 표가 함께 있는 엔티티 페이지
- `word-odyssey.md`: 제목 예외, 어원 변이, 실제형·표제형, Mermaid, 대형 형태론 표가 있는 단어 페이지
- `scott-1981-some-greek-terms.md`: 여러 용어와 긴 그리스어 인용이 있는 소스 페이지

각 파일의 작업:

- 프론트매터 데이터 정규화
- 제목·H1·aliases 정리
- 표제 페이지의 읽는 법 행 삽입
- 첫 언급 이후 일반 산문의 반복 삼중 표기 축소
- 실제 문헌학 구간의 그리스어 보존
- 1–3어와 4어 이상 형식 분리
- 긴 원문을 번역·원문·실제형 전사 순서로 정리
- 형태론·정형구 표의 전사 열 분리
- 전사값 문헌학 검수
- 해당 페이지를 레거시 목록에서 제거
- `updated` 날짜와 `wiki/log.md` 갱신
- 제목이나 공개 링크 표시가 바뀌면 색인 동기화

완료 조건:

- 네 문서가 `npm run check:greek`을 레거시 유예 없이 통과한다.
- 기존 출처·행 번호·논지·위키링크가 보존된다.
- 그리스어 실제형과 전사가 행 단위로 대응한다.
- 미확정 전사가 확정값으로 노출되지 않는다.
- Source mode에서 raw HTML 노이즈 없이 읽을 수 있다.
- Live Preview와 Reading view에서 읽는 법 행이 분명하지만 과도하게 강조되지 않는다.
- Quartz 375px에서 문서 전체 가로 스크롤이 생기지 않는다.
- 표만 자체 컨테이너에서 가로 스크롤한다.
- 라이트·다크·Reader mode에서 대비와 그리스어 글꼴이 정상이다.

### 단계 6. 시각 스타일 구현

수정 후보:

- `custom.scss`
- `.obsidian/snippets/ancient-fonts.css`
- 필요한 경우에만 `.obsidian/appearance.json`
- `DESIGN.md`

구현 원칙:

- 프론트매터 `cssclasses: [greek-reading-page]`를 안정적인 범위 지정자로 사용한다.
- 기존 `cssclasses` 배열을 덮어쓰지 않는다.
- Quartz에서는 실제 생성 DOM에서 클래스 적용을 확인한 뒤 읽는 법 행만 선택한다.
- Obsidian에서는 이미 활성화된 `ancient-fonts` snippet에 작은 메타데이터 스타일을 추가하는 방식을 우선한다. 새 snippet이 꼭 필요하면 생성 후 활성화 목록을 보존 병합한다.
- Source mode는 스타일 동일성을 요구하지 않는다. Markdown 줄 자체가 읽혀야 한다.
- 그리스어 글꼴은 기존 `Noto Serif` 폴백을 유지한다.
- 기존 CJK `word-break: keep-all`, 본문 폭, 색상 토큰과 조화를 유지한다.

완료 조건:

- 읽는 법 행만 선택되고 일반적인 H1 다음 문단은 오염되지 않는다.
- CSS 비활성 상태에서도 정보가 온전히 남는다.
- 페이지 상단의 정보 밀도가 기존보다 낮아진다.
- 200% 확대와 375px 화면에서도 내용 손실·겹침이 없다.
- 라이트·다크 대비가 충분하다.
- 카드·콜아웃·그림자·새 강조색이 없다.

### 단계 8. 단계별 전면 마이그레이션

파일럿 통과 뒤 다음 파동 순서로 진행한다.

#### 파동 1. 정식 표제 페이지와 템플릿

- 나머지 `wiki/concepts/concept-*.md`
- 나머지 `wiki/entities/entity-*.md`
- 나머지 `words/word-*.md`
- 세 템플릿

목표는 단일 원천과 제목·읽는 법 행을 먼저 안정화하는 것이다.

#### 파동 2. 분석 문서

- `wiki/analyses/analysis-*.md`

첫 언급 축소와 인용 구조를 적용하되 논증에 필요한 그리스어는 보존한다. 개념×문헌 매트릭스 생성 파일과 현재 사용자 변경이 겹치면 생성 스크립트의 소유 관계를 먼저 확인한다.

#### 파동 3. 고밀도 소스 문서

- `wiki/sources/*.md` 가운데 그리스어 밀도가 높은 문서부터
- 한 배치에 3–5개 문서

긴 원문과 실제형 전사에 가장 많은 수동 검토가 필요하므로 작은 배치로 제한한다.

#### 파동 4. 탐색·개요·저밀도 문서

- `wiki/index.md`
- `words/index.md`
- `wiki/overview.md`
- 루트 `index.md`
- Mermaid와 낮은 밀도의 남은 공개 문서

탐색 라벨에서 불필요한 그리스어를 제거하고, 필요한 경우 정식 페이지나 공개 안내로 링크한다.

#### 파동 5. 레거시 종료

- `scripts/legacy-greek-reading-pages.json`의 `pages`를 0으로 만든다.
- 전체 공개 코퍼스에 엄격 검증을 실행한다.
- 감사 문서의 완료 수치를 갱신한다.
- 안정화 후 레거시 파일과 분기 코드를 제거할지 ADR 후속 상태에 기록한다.

각 배치의 완료 조건:

- 배치 문서가 레거시 목록에서 제거됨
- 자동 검사 통과
- 해당 문서의 전사 검수 완료
- 제목 변경에 따른 색인·aliases·링크 동기화
- `wiki/log.md` 기록
- `git diff --check` 통과
- 시각적으로 영향이 큰 배치이면 375px·1280px 샘플 재검수

## 12. 기각한 대안

다음 대안은 첫 구현에서 채택하지 않는다.

### 모든 그리스어마다 한글·전사·IPA

문서 규모상 반복이 과도하고, 활용형·기능어·장문 인용까지 품질을 보장하기 어렵다. 비전공자에게 IPA는 또 하나의 학습 장벽이다.

### 전역 HTML ruby

브라우저에서는 유용할 수 있으나 Source mode의 HTML 노이즈, Obsidian Live Preview 차이, 위키링크와의 결합 문제, 대량 유지보수 비용이 크다. 향후 소수 표제어의 별도 실험으로만 검토한다.

### title 툴팁·hover 전용

터치·키보드·인쇄·CSS 비적용 환경에서 핵심 정보에 접근할 수 없다.

### CSS 생성 콘텐츠

검색·복사·접근성 트리·내보내기에 안정적으로 남지 않는다.

### aliases 또는 프론트매터만 추가

현재 공개 note properties가 숨겨져 있어 독자가 읽는 화면은 개선되지 않는다. 프론트매터는 단일 원천이고 읽는 법 행은 공개 표현층이다.

### 새 Quartz 컴포넌트

첫 구현의 범위와 유지보수 비용을 불필요하게 키운다. Markdown 계약이 안정된 뒤에만 별도 ADR로 검토한다.

### 현대 그리스어·고전 아티카·에라스무스식 중 하나를 “호메로스 발음”으로 표시

호메로스의 혼합 시어와 시대 차이를 감춘다. 이번 규약은 발음 재현이 아니라 호메로스어 지향 학술 전사다.

## 15. 새 세션에 전달할 최종 지시

사용자가 `다음 '구현 계획'에 따라 구현을 시작해`라고 말하면 이 문서를 승인된 실행 명세로 간주한다. 25개 설계 결정을 다시 열지 말고 단계 0부터 실행한다. 먼저 기준선과 사용자 변경을 보존하고, 규약·검증기·파일럿을 통과시킨 뒤에만 전면 마이그레이션한다.

새 세션이 물어야 하는 것은 취향이 아니라 실제 충돌뿐이다. 예를 들어 최신 저장소의 규칙이 이 계획과 양립하지 않거나, 미확정 전사에 필요한 권위 있는 근거가 없거나, 사용자 소유 변경과 같은 줄을 안전하게 병합할 수 없는 경우다. 그 외의 세부 구현 판단은 이 문서의 우선순위·표시 계약·수용 기준에 따라 진행한다.
