# homeric-oriented-v1 호메로스어 지향 학술 전사 규약

## 1. 지위와 목적

`homeric-oriented-v1`은 Homer Wiki에서 그리스어 원형과 실제 인용형을 로마자로 대조하기 위한 편집 규약이다. 이는 음성학적 재현, IPA, 낭송 지침, 또는 "정확한 호메로스 발음"의 주장이 아니다. 호메로스어는 이오니아어 중심에 아이올리스어와 고형이 섞인 전통적 시어이므로, 이 규약은 문자 대응과 독서 보조를 우선한다.

규약의 표준 출력은 화면에 보이는 학술 전사다. 관용 라틴명은 별도 정보이며 전사값으로 대체할 수 없다. 예를 들어 `Achilles`는 관용 라틴명이고 `Akhilleús`는 Ἀχιλλεύς의 학술 전사다.

이 문서는 전사와 편집 판단의 단일 운영 규약이다. 독자용 짧은 설명은 [[greek-reading-guide|그리스어 읽기 안내]]에 둔다. 표제 페이지의 필드와 표시 계약은 후속 데이터·템플릿 이행에서 이 규약을 그대로 따른다.

## 2. 적용 범위와 비적용 범위

적용 범위는 다음과 같다.

- 정식 표제 페이지의 `greek`, `transliteration`, `transliteration_system` 값
- 본문에 처음 완전 공개하는 핵심 용어
- 짧은 실제 인용형, 긴 원문의 실제형 전사, 형태론·정형구 표의 전사 열
- 기존 ASCII·장음 표기를 aliases 또는 호환 검색형으로 보존할 때의 표준값 판정

다음은 이 규약의 자동 확정 범위가 아니다.

- IPA, 음성 파일, 자동 TTS, 역사음 복원
- 텍스트에 없는 디감마의 복원
- 불분명한 α·ι·υ의 장단, 운율적 장단, 축약의 역사적 전개
- 판본·방언·필사 전통에 따라 달라지는 형태의 단일 정답화
- 관용 영어명, 한국어명, 라틴화된 신화 인명의 치환

## 3. 기본 원칙

1. 입력 그리스어는 편집 전에 Unicode NFC로 정규화한다.
2. 실제 인용형은 실제형 그대로 전사한다. 표제형의 전사를 굴절·활용형에 재사용하지 않는다.
3. 모음 길이와 악센트는 서로 다른 표지로 보존한다. 장모음은 macron, 악센트는 acute·grave·circumflex를 사용하며 하나의 표지로 두 정보를 겸하지 않는다.
4. 숨표는 발음 추측이 아니라 원문 철자 정보로 옮긴다.
5. 기본 표에 없는 문자·조합, 또는 표는 적용되지만 문헌학적 해석이 필요한 경우에는 추정하지 않고 예외 원장 검토 대상으로 남긴다.
6. 기존 `Mênis`, `mēnis`, `Menis` 같은 표기는 화면 표준으로 혼용하지 않는다. `μῆνις`의 표준 출력은 *mē̂nis*이며, 기존 표기는 aliases 또는 검색 호환값으로만 보존할 수 있다.

로마자 출력에는 가능한 경우 합성 문자를 쓰고, 장모음 위 악센트처럼 완전 합성 문자가 없는 조합에는 canonical combining sequence를 사용한다. 예를 들어 `μῆνις`의 η는 장모음 표지와 곡절악센트를 모두 보존하여 `ē` 뒤에 circumflex를 둔 *mē̂nis*로 적는다. 검증에서 NFC를 필수로 하는 값은 그리스어 키와 그리스어 프론트매터 값이며, 로마자 결합부호의 순서는 이 문서의 예시와 동일한 canonical 순서를 유지한다.

## 4. 문자 대응표

### 4.1 단순 모음

| 그리스어 | 표준 전사 | 비고 |
|:---:|:---:|:---|
| α, Α | a, A | 장단이 원문 철자만으로 확정되지 않으면 길이 표지를 추가하지 않는다. |
| ε, Ε | e, E | 짧은 모음으로 적는다. |
| η, Η | ē, Ē | 장모음 표지는 macron이다. |
| ι, Ι | i, I | 장단이 원문 철자만으로 확정되지 않으면 길이 표지를 추가하지 않는다. |
| ο, Ο | o, O | 짧은 모음으로 적는다. |
| υ, Υ | u, U | 호메로스어 지향 규칙의 기본값이다. 관용명 표기와 혼합하지 않는다. |
| ω, Ω | ō, Ō | 장모음 표지는 macron이다. |

### 4.2 이중모음과 ι 아래첨자

| 그리스어 | 표준 전사 | 적용 규칙 |
|:---:|:---:|:---|
| αι | ai | 각 글자를 보존한다. |
| ει | ei | 각 글자를 보존한다. |
| οι | oi | 각 글자를 보존한다. |
| υι | ui | 각 글자를 보존한다. |
| αυ | au | 각 글자를 보존한다. |
| ευ | eu | 각 글자를 보존한다. |
| ηυ | ēu | η의 장모음 표지를 보존한다. |
| ου | ou | 관용 철자와 별개로 문자 대응을 유지한다. |
| ᾳ | āi | α의 장모음성과 ι 아래첨자를 모두 드러낸다. |
| ῃ | ēi | η와 ι 아래첨자를 모두 드러낸다. |
| ῳ | ōi | ω와 ι 아래첨자를 모두 드러낸다. |

대문자 첫 글자와 ι 아래첨자의 조합은 표제어의 대문자 규칙을 따른다. 예를 들어 ᾨ는 `Ōi`로 시작한다. 편집자는 표의 문자 대응을 역사음의 단정으로 바꾸지 않는다.

### 4.3 자음과 자음군

| 그리스어 | 표준 전사 | 비고 |
|:---:|:---:|:---|
| β | b | |
| γ | g | γγ, γκ, γξ, γχ도 철자 대응을 우선하여 `gg`, `gk`, `gks`, `gkh`로 적는다. 음성적 `ng`를 자동으로 넣지 않는다. |
| δ | d | |
| ζ | z | |
| θ | th | |
| κ | k | |
| λ | l | |
| μ | m | |
| ν | n | |
| ξ | ks | |
| π | p | |
| ρ | r | 거친숨이 붙은 ῥ는 `rh`다. |
| σ, ς | s | 어말 ς도 `s`다. |
| τ | t | |
| φ | ph | |
| χ | kh | `ch`나 `x`로 바꾸지 않는다. |
| ψ | ps | |
| ϝ | w | 문자로 실제 제시된 디감마에만 적용한다. 텍스트에 없는 디감마를 복원하지 않는다. |

겹자음은 축약하지 않고 두 자음을 보존한다. 따라서 λλ은 `ll`, σσ는 `ss`다. 이 규칙은 음가를 단정하는 표기가 아니라 원문 철자의 추적성을 위한 것이다.

### 4.4 숨표, 악센트, 분음부호

| 원문 특징 | 표준 처리 | 예시 |
|:---|:---|:---|
| 매끈숨 | 로마자에 별도 표지를 넣지 않는다. | ἀγορά → *agorá* |
| 거친숨의 모음 | 모음 또는 이중모음 앞에 `h`를 둔다. | ἥρως → *hḗrōs* |
| 거친숨의 ρ | `rh`로 적는다. | ῥέω → *rhéō* |
| acute | 해당 모음 또는 이중모음의 악센트 위치에 acute를 둔다. | ἀγορά → *agorá* |
| grave | 원문에 grave가 실제로 있으면 grave를 보존한다. | ἀγορὰ → *agorà* |
| circumflex | 해당 모음에 circumflex를 보존한다. | μῆνις → *mē̂nis* |
| 분음부호 | 모음 분리를 나타내는 diaeresis를 보존한다. | Ἀτρεΐδης → *Atreïdēs* |

악센트가 이중모음의 δεύτε 글자에 놓이는 경우에도 로마자 대응 위치를 보존한다. 예를 들어 Ἀχιλλεύς는 *Akhilleús*다. macron과 악센트가 한 모음에 함께 필요한 경우 macron을 길이 표지로, acute·grave·circumflex를 악센트 표지로 각각 남긴다. 단, 미확정 장단을 운율이나 현대 관습만으로 보충하지 않는다.

## 5. 대소문자, 구두점, 단어 경계

- 원문의 첫 글자가 대문자이면 전사의 첫 대응 글자도 대문자로 쓴다. 나머지 철자는 원문에 맞추어 보존한다.
- 전부 대문자인 원문은 문서의 인용 정책과 문맥에 따라 전부 대문자 전사 또는 독서용 표제 대소문자를 선택할 수 있으나, 같은 표·인용 묶음 안에서 혼용하지 않는다. 이 선택이 판본 특성을 해칠 경우 review로 올린다.
- 원문의 공백, 하이픈, 줄바꿈은 가능한 한 유지한다. 장문 원문과 전사는 행 단위로 대응해야 한다.
- elision과 crasis의 아포스트로피는 원문의 절단을 보이는 `’`로 유지한다. 임의로 낱말을 복원하거나 재분절하지 않는다.
- 그리스어 가운데점 `·`은 `;`, 그리스어 물음표 `;`는 `?`로 옮긴다. 쉼표와 마침표는 대응하는 현대 구두점으로 유지한다.
- 문헌 인용의 편집 기호, lacuna, 의심스러운 글자, 비정규 문자, 판본 특수기호는 임의로 지우거나 정규화하지 않는다. 필요한 처리 방식은 예외 원장이나 인용 주석에서 검토한다.

## 6. 편집 적용 규칙

### 6.1 표제 페이지와 첫 공개

개념·엔티티·단어의 마이그레이션된 표제 페이지는 프론트매터의 `korean_name`, `conventional_latin`, `greek`, `transliteration`, `transliteration_system: homeric-oriented-v1`을 단일 원천으로 사용한다. 읽는 법 행은 H1 바로 아래의 첫 비어 있지 않은 본문 줄에 다음 순서로 둔다.

```markdown
**[[greek-reading-guide|읽는 법]]**: {korean_name} · **원어**: {greek} · **학술 전사**: *{transliteration}*
```

이 행 뒤 일반 산문에서는 한국어명을 기본으로 한다. 같은 개념을 문서 전체에서 처음 완전 공개한 뒤에는 그리스어와 전사를 매번 반복하지 않는다. 철자·방언·형태론을 논증하거나 실제 원문을 인용하는 구간만 다시 완전 표기를 쓴다.

### 6.2 짧은 형식과 긴 원문

그리스어가 1–3어이고 완결된 절·시행이 아니면 인라인으로 둔다. 실제형은 그 실제형으로 전사한다.

```markdown
메니스(μῆνιν, *mē̂nin*)는 ...
```

그리스어가 4어 이상이거나 완결된 절·시행이면 다음 순서를 지킨다.

```markdown
- **번역**: 한국어 번역문
- **원문**: *그리스어 실제 인용문*
- **학술 전사**: *위 원문과 행 단위로 대응하는 실제형 전사*
```

직접 인용에는 블록인용을 쓰지 않는다. 긴 원문의 전사는 표제형 전사나 임의의 관용 라틴명으로 대체하지 않는다.

### 6.3 형태론·정형구 표

형태론·정형구 표는 그리스어와 학술 전사를 같은 셀에 섞지 않는다. 최소한 다음 열을 분리한다.

| 그리스어 실제형 | 학술 전사 | 표제형·형태론 | 한국어 풀이 | 근거 |
|:---|:---|:---|:---|:---|
| 실제형 | 같은 실제형의 전사 | 형태 정보 | 문맥상 뜻 | 서·행 또는 사전 |

모바일에서 표가 넓으면 표 컨테이너 안에서만 가로 스크롤한다. 전사 열을 숨기거나 본문 전체에 가로 넘침을 주지 않는다.

## 7. 검토와 예외

다음은 기본표를 기계적으로 적용해 확정하면 안 되는 review/exception 영역이다.

| 영역 | 기본 처리 | 검토가 필요한 이유 |
|:---|:---|:---|
| α·ι·υ의 장단 | 원문 철자만으로 확정되지 않으면 표지 추가 금지 | 사전형, 운율, 방언, 편집 전통이 함께 필요할 수 있다. |
| 디감마 | 실제 문자 ϝ에만 `w` | 결손 디감마의 복원은 판본·운율 해석이다. |
| 축약·crasis·elision | 보이는 철자와 절단만 옮김 | 복원형을 어느 수준에서 제시할지 편집 판단이 필요하다. |
| 방언형·고형 | 실제 판본형을 보존 | 표준 아티카형으로 정규화하면 증거가 사라질 수 있다. |
| 악센트·분음부호가 불안정한 판본 | 판본값을 임의 교정하지 않음 | 판본·사전·학술 근거의 대조가 필요하다. |
| 장단과 운율의 상호작용 | 자동 길이 부여 금지 | metrical length가 어휘 장단과 같지 않을 수 있다. |
| 고유명사의 관용 라틴화 | 관용명과 전사를 분리 | 신화·영어 관습은 문자 대응과 다를 수 있다. |
| 비정규 문자·손상·판본 기호 | 임의 변환 금지 | 전사 이전에 텍스트 비평 판단이 필요하다. |

예외는 `scripts/greek-transliteration-exceptions.json`에 그리스어형, 제안 전사, 근거, 위치, 상태, 검토자를 남긴다. `review` 항목은 제안일 뿐이며 읽는 법 행·인용·표의 확정 전사로 쓸 수 없다. `approved`가 되려면 승인값, 근거, 검토자, 검토일이 모두 있어야 한다. `rejected` 항목은 거부 이유를 기록하고 그 제안을 공개 표준으로 사용하지 않는다.

## 8. 근거와 검증

규약을 해석하거나 예외를 검토할 때는 다음 순서로 근거를 우선한다.

1. Chiara Bozzone, *Homer's Living Language*의 transliteration note
2. 실제 사용 판본의 원문과 서·행 정보
3. 신뢰할 수 있는 고대 그리스어 문법·사전
4. 악센트, 장단, 방언을 다루는 학술 자료
5. Unicode의 Greek 정규화 설명

블로그, 무출처 발음 사이트, 자동 TTS, 자동 변환 결과만으로 전사값을 승인하지 않는다. 자동화는 NFC, 필드, 제목, 읽는 법 행, 표와 인용의 구조를 검사할 수 있지만 전사값의 문헌학적 정답을 판정하지 않는다.

## 9. 버전 정책

`homeric-oriented-v1`의 규칙을 명료화하되 기존 출력과 호환되는 수정은 이 문서의 `updated` 날짜와 변경 기록으로 남긴다. 기존 출력이 달라지는 변경, 새 문자 대응, 악센트·길이 정책 변경, 예외 상태의 의미 변경은 새 버전 식별자를 만들고 마이그레이션 범위와 aliases 호환을 기록한다.

새 버전은 기존 전사를 일괄 치환하기 전에 표제 페이지, 실제형 인용, 표, 예외 원장, 검색 별칭, 검증기를 함께 검토해야 한다. IPA·음성은 이 규약의 다음 버전으로 자동 승격되지 않으며 별도 결정과 제한된 파일럿을 요구한다.
